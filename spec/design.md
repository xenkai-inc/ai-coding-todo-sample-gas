# シンプルTODO デザイン方針

> 目次: [仕様インデックス](index.md) ／ 技術仕様: [README](../README.md)
>
> このファイルは UI 全体で共通して守る **デザインの方針** です。
> 機能ごとの動作は各 `spec/<機能名>.md` に、見た目の方針はここにまとめます。
> `/design` スキル（ui-ux-pro-max）を使って下書きしました。

---

## 1. 全体方針

- **誰向け / どんな場面**：業務のタスクを自分用に管理する人（非エンジニア含む）が、毎日サッと開いて使う
- **トーン**：信頼感・堅実・落ち着き（業務ツールらしい、余計な装飾のない静けさ）
- **デザインの方向性（STYLE）**：ミニマル＋マイクロインタラクション（1画面・余白広め・操作へのささやかな反応）。**常にライトトーン固定**（OS のダークモード設定に追従しない。受講者全員が同じ明るい見た目になるよう1トーンに固定）
- **既存パターンとの関係**：新規プロジェクトのため、ui-ux-pro-max の推奨（モノクロ＋青アクセント）を採用。フォントのみ下記理由で差し替え

---

## 2. 配色（カラートークン）

ui-ux-pro-max 推奨の「モノクロ＋青アクセント」を採用（コントラスト良好で業務ツール向き）。

| 用途 | トークン | 値 |
|---|---|---|
| Primary（主役の色 / 追加ボタン） | `--color-primary` | `#18181B` |
| On Primary（その上の文字色） | `--color-on-primary` | `#FFFFFF` |
| Accent / CTA（強調） | `--color-accent` | `#2563EB` |
| Background（背景） | `--color-background` | `#FAFAFA` |
| Foreground（文字） | `--color-foreground` | `#09090B` |
| Muted（控えめな要素 / 完了タスクの文字） | `--color-muted` | `#71717A` |
| Border（境界線） | `--color-border` | `#E4E4E7` |
| Destructive（削除ボタン） | `--color-destructive` | `#DC2626` |

> このアプリは **常にライトトーン固定** とし、ダークモードには切り替えない（`prefers-color-scheme` は使わない）。
> 実装では CSS 変数（`--color-*`）で定義し、値をコードに直書きしない。

---

## 3. タイポグラフィ（フォント）

- **見出し・本文とも**：**Inter**（読みやすい定番のサンセリフ）
- **読み込み方法**：Google Fonts を CSS `@import` で読み込み、`font-display: swap`

```css
@import url('https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&display=swap');
```

> **推奨からの変更点（理由）**：ui-ux-pro-max の推奨フォントは Lora / Raleway（癒し・ウェルネス向けのセリフ系）でした。
> 今回は「業務タスク管理・信頼感」がテーマなので、堅実で可読性の高い **Inter** に差し替えました。
> 数字（件数など）が揃って見えるのも業務ツール向き。

---

## 4. 余白・サイズ

- 使う余白スケール：**4 / 8 / 12 / 16 / 24 / 32 px**（バラバラの値を使わない）
- 角丸：**8px**（入力欄・ボタン・タスク行）
- 影：控えめに1段階（カード状のまとまりだけ薄く）
- コンテンツ幅：中央寄せ・最大 **560px**（1画面のTODOに集中できる幅）

---

## 5. コンポーネント方針

素の HTML + CSS で作る（フレームワークなし）。主な部品：

- **入力欄（Input）**：横長のテキスト入力＋右に「追加」ボタン。Enter でも追加できる
- **タスク行（Task row）**：左にチェックボックス、中央にタスク文字、右に「削除」ボタン。ホバーで薄く背景色
- **ボタン**：
  - 追加 = Primary（濃色・白文字）
  - 削除 = Destructive の色は文字/アイコンに使い、普段は控えめ。ホバーで赤を強める
- **空状態（Empty state）**：タスクが1件もないとき「まだタスクがありません。上の欄から追加しましょう」と案内を出す

---

## 6. このアプリで避けること（AVOID）

- 絵文字をアイコン代わりに使う（素人っぽく見える。SVG アイコンを使う）
- 過剰な装飾・強い影・派手なアニメーション（業務ツールの落ち着きを壊す）
- 複雑な導入フロー（開いたらすぐ使える）
- 待たせっぱなしの動作（保存はスプレッドシートなので 1 秒前後かかる。保存中・読み込み中は一言表示し、二重に押せないようにする）

---

## 7. GAS の画面の制約（このアプリで守っていること）

- CSS・JS は `Index.html` 1 ファイルにまとめる（Google Fonts は https の CDN から読み込む）
- スマホ表示の設定（viewport）は `Code.gs` の `doGet` で `addMetaTag` を使って付ける（`.html` に書いても効かない）
- リンクは囲い（iframe）の外で開くよう、`<base target="_top">` を入れている
- アイコンはインライン SVG（画像ファイルは置かない）

---

## 8. モダンUIチェックリスト（仕上げ前に確認）

- [ ] アイコンは絵文字でなく SVG（削除アイコンなど。Lucide / Heroicons 相当を inline SVG で）
- [ ] クリックできる要素に `cursor: pointer`
- [ ] ホバー時になめらかに変化（transition 150〜300ms）
- [ ] 文字と背景のコントラスト（本文 4.5:1 以上。完了タスクの muted 文字も薄すぎないか確認）
- [ ] キーボード操作で focus リングが見える（追加・チェック・削除まで Tab で回せる）
- [ ] 余白に一貫性がある（上のスケールだけを使う）
- [ ] スマホ表示で崩れない（375 / 768 / 1024px）
- [ ] prefers-reduced-motion を尊重（動きを減らす設定を尊重）
- [ ] 常にライトトーン固定（OS がダークモードでも明るい見た目のまま）
