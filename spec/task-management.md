# タスク管理（追加・完了・削除）

> 目次: [仕様インデックス](index.md) ／ 技術仕様: [README](../README.md)
>
> このファイルは1つの機能の仕様です。機能ごとに1ファイル作ります。

---

## 概要

1画面のTODOで、タスクを **追加**・**完了/未完了の切り替え**・**削除** できる。締切などは持たない、業務タスクの最小の管理機能。

---

## 動作

1. 画面上部の入力欄に、やることを1行で入力する
2. 「追加」ボタン（または Enter キー）で、タスクが一覧の末尾に追加される
3. 各タスクの左のチェックボックスをクリックすると、完了/未完了が切り替わる
4. 完了したタスクは、文字に **打ち消し線** が付いて見た目で区別できる
5. 各タスクの「削除」ボタンで、そのタスクが一覧から消える
6. 保存中は「保存しています…」と表示し、その間は追加・切り替えを受け付けない

---

## 受け入れ基準（AC）

> **AC（受け入れ基準）**：「Acceptance Criteria」の略で、「これができたら完成」と言える条件のこと。
> **確かめ方** は 2 種類です。
> - **自動テスト**：答えが 1 つに決まるもの。PC の中で何度でも確かめられます（`tests/todo.test.js`）
> - **確認用 URL**：画面の見た目・操作。確認用 URL を開いて目で確かめます

| AC | 条件 | 確かめ方 |
|---|---|---|
| AC-1 | タスクを追加すると、一覧の末尾に加わる | 自動テスト |
| AC-2 | 空文字（何も入力していない / 空白のみ）は追加できない。前後の空白は取り除かれる | 自動テスト |
| AC-3 | 完了にしたタスクは、打ち消し線が付いて見た目で完了と分かる | 判定は自動テスト／見た目は確認用 URL |
| AC-4 | チェックを外すと、完了が解除され打ち消し線が消える | 判定は自動テスト／見た目は確認用 URL |
| AC-5 | 削除したタスクは、一覧から消える | 自動テスト |

> AC-3・AC-4 は「完了かどうかの切り替え（判定）」と「打ち消し線（見た目）」の 2 つを含んでいます。
> 判定は `toggleTask` のテストで、見た目は確認用 URL で確かめます。

## データモデル

```
Task
- id: string        … タスクを見分けるための文字列（Code.gs で自動で付ける）
- title: string     … タスクの内容（1行）
- done: boolean     … 完了しているか（true = 完了）
- createdAt: number … 追加した日時（ミリ秒。並び順や後の拡張のため）
```

一覧は Task の配列として1つ持つ。
保存の仕様は [sheet-persistence.md](sheet-persistence.md) を参照。

> 【拡張のためのメモ】締切機能を足すときは、この Task に `dueDate`（'yyyy-MM-dd' の文字列・任意）を1つ加え、
> `Code.gs` の `TASK_COLUMNS` に `'dueDate'` を足すだけで、シートの列も増える構造にしてある。
> 既存の追加/完了/削除には手を入れずに拡張できるのが狙い。

## この機能で扱う大事なデータ

- [x] どれも扱わない（保存するのは利用者本人が書いたタスクの文字列のみ。個人情報・秘密情報・お金の情報は扱わない）

---

## 非機能要件（必要な場合のみ）

- **性能**：タスク件数は個人利用の想定（〜数百件）。保存は 1 回 1 秒前後かかるため、保存中は表示で知らせ、二重に操作させない。
- **セキュリティ**：
  - 入力されたタスクの文字列を画面に表示する際、HTML として解釈させず、文字としてそのまま表示する（`textContent` を使う）
  - 空文字のチェックは画面と `Code.gs` の両方で行う（画面のチェックだけに頼らない）
  - 画面に返すのはタスクの一覧だけ（保存先のスプレッドシートの ID などは返さない）

## 未確定事項

- タスクの並び順は「追加順（古い→新しい）」で確定。並び替えは別機能として後から足す想定。
- タスクの編集（追加後に文言を直す）は、ベースには入れない。必要になったら別途仕様化する。
